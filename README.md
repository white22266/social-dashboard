# Content Performance Review: AINCHORS (Instagram + TikTok)

A React + TypeScript + Tailwind + Recharts dashboard built on real public post data collected with Apify on 28 Sep 2026.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # static site in dist/ (open from any folder)
npx tsx scripts/report.ts   # print every calculated metric in the terminal
```

## How it is organised

| Layer | Files | Changes when data is refreshed? |
|---|---|---|
| Raw scrape | `data-raw/*.json` | yes |
| Normalised dataset | `src/data/social-data.json` | yes (generated by `scripts/normalize.py`) |
| Topic & hook labels | `src/data/annotations.json` | hand-assigned; new posts fall back to keyword rules in `src/lib/classify.ts` |
| Calculations | `src/lib/analytics.ts`, `src/lib/stats.ts` | no. All numbers are computed live from the dataset |
| AI commentary | `src/data/insights.json` (typed in `insights.ts`) | yes: rewritten by Ollama on each refresh and fact-checked against the computed metrics |
| Presentation | `src/components/*`, `src/pages/Dashboard.tsx` | no |

## Refreshing the data

**From the website:** press **Refresh data & AI analysis** → GitHub's *Request refresh* page → **Run workflow**
(only repository collaborators can). The owner's Mac picks the request up within a minute and runs
`scripts/refresh.sh`:

1. `scripts/fetch_apify.sh --full`: Apify scrape (about $0.24 per run; free plan = $5/month)
2. `scripts/ai_refresh.py`: Ollama (default `kimi-k3:cloud` with thinking; fallbacks `deepseek-v4-pro:cloud`,
   `glm-5.3:cloud`, override with `OLLAMA_MODELS`) classifies new posts and rewrites `src/data/insights.json`.
   `scripts/validate_insights.py` rejects any draft containing a number that is not in `scripts/facts.ts`
   output; if all drafts fail, the previous commentary is kept and the page says so.
3. typecheck, lint and build, then commit and push. GitHub Pages redeploys in about a minute.

The Mac must be on, logged in, with Ollama running. A notification appears when a refresh starts and ends.
Log: `~/Library/Logs/social-dashboard-refresh.log`. Watcher: `bash scripts/install_watcher.sh`
(`--uninstall` to remove).

By hand: `bash scripts/refresh.sh`. Data only: `bash scripts/fetch_apify.sh --full`.

## Password-protected Refresh button (Cloudflare Worker)

`worker/` is a tiny Cloudflare Worker: the site POSTs the password there, the Worker compares it with the
`REFRESH_PASSWORD` secret (5 wrong tries per IP → 15-minute lock; 10-minute cooldown between refreshes)
and, if correct, dispatches the *Request refresh* workflow with a fine-grained `GITHUB_TOKEN` secret
(this repo only, Actions read/write). The password is never in the site code or this repository.
The site finds the Worker through `src/lib/config.ts` (`REFRESH_API`).

```bash
cd worker && npm install
npx wrangler login
npx wrangler kv namespace create GUARD    # put the id in wrangler.toml
npx wrangler deploy
npx wrangler secret put REFRESH_PASSWORD
npx wrangler secret put GITHUB_TOKEN
```

## Data rules

- Missing metrics are `null`, never 0. Instagram share counts are not public, so Instagram engagement = likes + comments.
- Instagram views = Reel play count. Image and carousel posts have no view count.
- Engagement per 1,000 = (likes + comments + shares) / views × 1000. "Pooled" uses totals; "typical" is the median of per-post rates.
- Day and time analysis uses Asia/Kuala_Lumpur.
- Thumbnails are downloaded to `public/thumbnails/` because the platform CDN links expire.
